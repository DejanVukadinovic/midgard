# Threat model

Scope: MIDGARD core, shared libraries, the sample service/SDK, and the Compose stack. Assets: tenant data, registry integrity (contracts, bindings, grants), credentials, audit trail.
Trust boundaries: browser/mobile (untrusted) · application facades (trusted for their own logic, **not** for identity claims) · implementations · core · IdP · PostgreSQL · operators.

| # | Threat | Mitigation (implemented) | Test | Residual risk / planned |
|---|---|---|---|---|
| T1 | **Spoofed application identity** (app A claims to be B via a field/header, or reuses B's user token) | identity only from the verified token's `client_id`; user tokens must be issued to a client of the calling application; request fields ignored | `tenancy.rs::spoofing_and_unauthorized_access_is_denied`, acceptance | Compromised client credentials are indistinguishable from the app — rotate; prefer private-key-JWT client auth |
| T2 | **Forged tenant / organization selection** | organization is a selection checked against verified role claims; tenant looked up by `(org, app)`; caller-supplied tenant headers ignored; RLS as second layer | same + `rls_*`, acceptance | Depends on IdP claim fidelity (ADR-002 spike) |
| T3 | **Machine token used as user authorization** | machine tokens carry no project roles ⇒ no tenant context | `tenancy.rs` (IAM-09) | — |
| T4 | **Token forgery / confusion** (`alg=none`, HS256, foreign key, wrong aud/iss, expired, ID token as access token) | RS256/ES256 only, JWKS by `kid`, issuer allowlist, audience, `exp/nbf/iat`, lifetime cap, ID-token rejection | `security.rs::forged_and_misissued_tokens_are_rejected` | Revocation window = token lifetime |
| T5 | **Compromised registration credentials** (deployment identity) | identities are slug-scoped (`example-*`), cannot publish contracts, create apps or grant themselves; operators can revoke; every change audited; operator/publisher are static allowlists | `resolver.rs`, `security.rs::non_operators_cannot_use_admin_apis` | A stolen deployment identity can re-register *its own* slugs (change endpoint). Mitigate: short-lived credentials, endpoint allowlist, alert on audit `implementation.register` |
| T6 | **Malicious endpoint registration / SSRF** | scheme/host policy (no IPs, localhost, metadata names, credentials, queries), optional strict allowlist, probe resolves DNS and refuses loopback/link-local, no redirects, registry never fetches caller-supplied URLs | `endpoint_policy` unit tests, `resolver.rs` (SVC-04) | DNS rebinding between check and connect is narrowed, not eliminated; pin to network policy in production |
| T7 | **Unauthorized contract binding / grant** | operator-only; grants ≠ bindings; both audited with before/after; resolver requires both | `resolver.rs`, `security.rs` | Operator account compromise is game over — protect and monitor |
| T8 | **Contract tampering** (silent change of a published version, substituted digest) | immutable by constraint + DB trigger; content digest; implementations must claim the exact digest | `registry.rs::contract_publication_and_immutability`, CON-08 | Claimed ≠ conformant; CI conformance evidence recommended |
| T9 | **Cross-implementation data split** (traffic silently shifts to another stateful implementation) | explicit bindings, no automatic failover | `resolver.rs` (SVC-08) | — |
| T10 | **Direct calls bypassing the registry** (knows the URL) | implementations verify audience-correct tokens and confirm grant+binding with core | `service.rs`, acceptance (RES-02/RES-10) | Authorization decision cached ≤ 15 s in the sample service |
| T11 | **Cross-tenant SQL access** (app bug) | PostgreSQL RLS (FORCE), non-owner/NOBYPASSRLS role, transaction-local context | `tenancy.rs`, `service.rs` | Superuser/owner connections bypass RLS — never use them at runtime |
| T12 | **Injection** (SQL, JSON, header) | parameterized SQLx everywhere; strict validation of slugs, versions, URLs; bounded body sizes | `security.rs::sql_injection_attempts_are_inert` | — |
| T13 | **DoS via registration/resolve floods or huge bodies** | process-wide rate limit on admin routes, body limits, request timeouts, bounded pools | `security.rs::rate_and_body_limits` | Per-identity limits and edge rate limiting are future work |
| T14 | **Secret leakage** (logs, repo, images) | secrets via files/Docker secrets; headers not logged (including at the edge); gitleaks on full history; log scan in acceptance | acceptance, CI `security` | Dev fixtures are public by design (`dev-only-*`) |
| T15 | **Audit tampering** | append-only trigger for all roles incl. TRUNCATE | `operations.rs::audit_log_is_append_only` | Superuser can drop triggers — ship audit to external storage in production |
| T16 | **Stale authorization** (revoked but still allowed) | DB-backed checks per request; short token lifetime cap; SDK never serves stale after denial | tests above | IdP-side revocation latency unmeasured |
| T17 | **Compose stack mistaken for production** | docs/labels, loopback-only ports, dev IdP prints warnings | `ports.sh` | Operator responsibility |
